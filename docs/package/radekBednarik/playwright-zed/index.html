#Playwright Runner

A Zed extension that runs and manages Playwright end-to-end tests from the editor. The goal is feature parity with the Playwright VS Code extension, delivered through the surfaces Zed gives extensions. Progress per upstream capability is tracked in docs/parity.md.

Documentation with screenshots: https://radekbednarik.github.io/playwright-zed/

Work in progress. Today the extension runs a test, a describe group or a file from the editor, re-runs the last run, picks the Playwright projects (browsers) a run uses, shows the executing step and per-step durations inline, opens the full run output, records traces and opens them in Playwright's trace viewer, and runs tests in a visible browser that stays open between runs. The remaining upstream capabilities are listed with their status in docs/parity.md. Expect rough edges, breaking changes between minor versions, and gaps compared to the VS Code extension. Bug reports and feedback are welcome in the issue tracker.

This is an independent community extension. It is not affiliated with, endorsed by, or maintained by Microsoft or the Playwright team. "Playwright" is a trademark of Microsoft Corporation; the name is used only to describe what this extension works with. The extension contains no code from the Playwright projects and drives the Playwright installed in your own workspace through its public command line.

The extension is developed with AI assistance (GitHub Spec Kit driven by Claude Code); every change is reviewed and verified by the maintainer. Details are in Built with AI assistance at the end of this document.

#Requirements

  • Zed stable 1.23 or newer.
  • Node.js 22 or newer on your PATH (Zed may also provide its own Node).
  • @playwright/test v1.38 or newer installed in your project, with browsers installed (npx playwright install).

#Install

From the Zed extension registry. Open zed: extensions and search for Playwright Runner. The listing is under review in the Zed extension registry (zed-industries/extensions#7975); the submission process is described in docs/publishing.md. Until the review completes, install from source.

From source, for the unreleased version or while the registry listing is under review:

  1. rustup target add wasm32-wasip2

  2. cd server && npm install && npm run build

  3. In Zed, run zed: install dev extension and pick this repository's root. If you installed a dev extension before 0.4.0, it is listed as "Playwright for Zed" with the id playwright; uninstall it in zed: extensions first, otherwise two Playwright language servers start on the same files.

    Files that are already open when the extension is installed are picked up without closing and reopening them (verified on Zed 1.24.2). One exception: after an update, a reinstall, or a rerun of zed: install dev extension in the same Zed session, Zed keeps the Playwright server stopped. It marks the server as manually stopped when the old extension version unloads and never clears the mark, so no file is served, open before or after. Run editor: restart language server from any TypeScript or JavaScript file of the project, or restart Zed; closing and reopening files does not help. Tracked in Zed as zed-industries/zed#60405 (the remote variant of the same mechanism).

The extension installs the language server package playwright-zed-language-server from npm on first use. Nothing is bundled. To run a locally built server instead, see Building from the repository.

#What it does

  • Detects Playwright workspaces (any playwright.config.{ts,js,mts,mjs,cts,cjs} with @playwright/test v1.38 or newer resolvable next to it, monorepos included).
  • Runs nothing from a folder until it is trusted, because test discovery executes the workspace's Playwright configuration and test files. On Zed 0.218 or newer, trusting the folder in Zed is enough; older Zed releases get a question once per workspace and session.
  • Discovers tests through Playwright's own --list and shows Run test and Run describe code lenses above each test and group.
  • Run test at cursor, Run describe at cursor, Run file and Re-run last as code actions (ctrl-. / cmd-.).
  • Picks the Playwright projects (browsers) to run in, one, several or all, from the same menu; the choice is remembered per config across restarts, and a folder default can be set in Zed settings (see Projects).
  • Runs happen through the Playwright installed in your workspace, headless. Results arrive as a progress indicator, a pass/fail notification, an error marker on each failing line, and the full output in Zed's language server log (dev: open language server logs).
  • While a test runs, the step that is executing right now carries a ⌛ waiting… label at the end of its line; afterwards every step line shows how long it took (2003ms, or 2003ms (ran 2×) when the line ran in two projects). The labels are inlay hints, see Settings.
  • Show last run output opens the complete output of the latest run (the command line, Playwright's own report, everything the test printed) in an editor tab.
  • Show trace viewer records a trace for every run and opens Playwright's trace viewer for it; Show browser runs tests in a visible browser window that stays open between runs, and Close all browsers closes it (see Usage).

#Settings

Code lenses are off by default in Zed. To see the run buttons above tests, add to your Zed settings:

{
  "code_lens": "on"
}

Use "menu" instead to list lenses inside the code action menu.

Inlay hints are off by default in Zed as well. The executing-step label and the per-step durations are inlay hints, so they appear only with:

{
  "inlay_hints": {
    "enabled": true
  }
}

Both settings can live under "languages": { "TypeScript": { ... } } if you prefer them per language. Without them the extension runs tests exactly the same; only the labels are absent.

Folder or team defaults for the extension's own options live in one settings block, in .zed/settings.json of the repository or in your user settings. Each key applies until you toggle the option yourself in the editor; changes take effect without a restart:

{
  "lsp": {
    "playwright": {
      "settings": {
        "projects": ["chromium", "firefox"],
        "showTrace": false,
        "reuseBrowser": false
      }
    }
  }
}
  • projects: the projects selected by default, see Projects.
  • showTrace: record and show traces by default, see Trace viewer.
  • reuseBrowser: show the browser by default, see Show browser and close all browsers.

The extension remembers your in-editor choices in small JSON files owned by your user, outside the repository:

OSLocation
Linux$XDG_STATE_HOME or ~/.local/state/playwright-zed-language-server/
macOS~/Library/Application Support/playwright-zed-language-server/
Windows%LOCALAPPDATA%\playwright-zed-language-server\

Set PLAYWRIGHT_ZED_STATE_DIR in the environment Zed starts from to move it. The folder holds project-selection.json, trace-viewer.json, show-browser.json and a runs/ folder with the latest run output per workspace.

#Usage

#Before the first run: test discovery

Test discovery executes the workspace's Playwright configuration and test files, so it only runs in folders you trust.

Zed 0.218 or newer. Zed asks whether you trust a folder (Restricted Mode) and starts language servers only after you do. That answer is the only question: the Playwright server discovers tests at once and Zed remembers the trust across restarts, much like Workspace Trust protects the upstream VS Code extension.

  • To revoke trust, run workspace: clear trusted worktrees (it clears every trusted folder and restarts Zed).
  • "session": { "trust_all_worktrees": true } in your user settings makes discovery run in every folder without asking, as turning off Workspace Trust does in VS Code.
  • Inside a dev container Zed applies no worktree trust, so discovery runs without a question once you have chosen Open in Container.

Older Zed releases and other editors. The Playwright server shows one notification: it names the folder, explains that discovery executes the workspace's Playwright configuration and test files, and offers Run discovery and Not now. The same question appears on any Zed release when a folder reaches the server only as a root URI rather than as a workspace folder.

  • Run discovery starts discovery at once; lenses and run actions appear and nothing asks again until Zed is restarted or the folder is closed.
  • Not now, or closing the notification, keeps the extension idle for that folder: nothing from it is executed and no run actions are offered. To change your mind, open any file in the folder, press ctrl-. and choose Playwright: Enable test discovery.
  • The answer is remembered for the editing session only; each root folder is asked separately. Reading the installed Playwright version never executes workspace code, so the "version too old" warning can appear before you answer.

Notes:

  • Runs use the file on disk. If the buffer has unsaved changes you get a warning and the saved version runs.
  • Starting a run while one is in progress cancels the first one.
  • A failing test leaves an error marker at the failing line until you edit the file or run again. With two or more projects, each failing project gets its own marker and the message starts with the project in brackets, for example [mobile] adds numbers: ....
  • With several configuration files, the one nearest to the test file is used.
  • Playwright below v1.38 produces a single warning and disables running.
  • After toggling a project, the trace viewer or the browser option, a notification confirms the new state. Zed keeps the ctrl-. menu cached per cursor position, so reopening it at the very same spot still shows the old [x] marks; move the cursor (another line is enough) and the menu is refetched with the current state.

#Projects

Playwright runs each test once per project of your playwright.config.*, and most projects name a browser. Like the VS Code extension, the runner starts with the first project selected; a configuration with a single project behaves exactly as before and shows no picker. In any file that belongs to a configuration with two or more projects, ctrl-. lists them as Playwright: [x] chromium, Playwright: [ ] firefox, and so on. Choosing an entry toggles that project; at least one stays selected. Playwright: Select all projects selects every one. Runs pass the selected projects to Playwright (no filter when all are selected), the run lenses show only tests that run in a selected project, and the progress message names the projects used.

The choice is remembered per configuration file in project-selection.json under the state directory listed in Settings. A project that disappears from the configuration is dropped from the selection with one notice; a new project stays unselected until you pick it.

A team default for a folder is the projects key of the settings block in Settings; it applies when you have not picked anything yet. Names the configuration does not define produce one warning listing the available projects. This setting is specific to the Zed extension; the upstream VS Code extension has no equivalent.

Every toggle is confirmed by a notification naming the projects now selected (see the menu caching note under Actions).

#Step labels and run output

  • While a test runs, the executing step carries a ⌛ waiting… label at the end of its line; afterwards every step line shows its duration. Step labels follow the file: an edit removes the durations of that file (their lines may have moved), the next run removes all of them, and closing and reopening an unedited file brings them back. Steps inside helper files and page objects are labelled there. The labels need inlay hints turned on, see Settings.
  • Playwright: Show last run output opens the complete output of the latest run in an editor tab. The output is written to the runs/ folder under the state directory, one file per workspace, latest run only, and opened as a normal buffer. Zed keeps the tab in sync with the file, so the next run updates it in place. Put the cursor on a tests/foo.spec.ts:12:7 reference and use editor: open selected filename to jump there.

#Trace viewer

Like the VS Code extension's Show trace viewer checkbox, Playwright: [ ] Show trace viewer (in the ctrl-. menu of any file that belongs to a Playwright configuration) makes every run record a full trace and opens Playwright's own trace viewer window for it:

  • Run a single test (▶ Run test or Run test at cursor) and the viewer opens with that test, following it while it runs and showing the final trace when it ends. Later single-test runs reuse the same window. If you close the window, the next trace opens a new one.
  • After Run file, Run describe or Re-run last, put the cursor inside a test and choose Playwright: Show trace to see that test's trace from the last run. A test that recorded none (skipped, or not part of the run) gets a message instead.
  • Choose Playwright: [x] Show trace viewer again to turn it off: the window closes and runs go back to your configuration's own trace setting. Every toggle is confirmed by a notification, for the same menu-caching reason as the project picker.

While it is on, runs pass --trace on to Playwright, so they take a little longer and test-results/ holds a trace.zip per test; Playwright manages those files, the extension never deletes them. The viewer is started from your project's own Playwright (playwright show-trace), so it needs the Chromium that npx playwright install provides; if it cannot start, you get one error notification with the command, and the run itself is unaffected.

The choice is remembered per user in trace-viewer.json under the state directory. A folder or team default is the showTrace key of the settings block in Settings and applies until you toggle the option yourself.

#Show browser and close all browsers

Like the VS Code extension's Show browser checkbox, Playwright: [ ] Show browser (in the ctrl-. menu of any file that belongs to a Playwright configuration) makes every run open a visible browser window and keeps that browser alive between runs:

  • Runs go through the browser one test at a time (--headed --workers 1), so you can watch what the test does. The window stays open after the run with the last page still shown, and the next run continues in the same window. Close the window by hand and the next run opens a new one.
  • Playwright: Close all browsers closes the kept browser without changing the option; the next run opens a fresh one. It is refused while a run is in progress.
  • Choose Playwright: [x] Show browser again to turn it off: the browser closes (after the current run, if one is in progress) and runs go back to headless with your configuration's own worker count. Every toggle is confirmed by a notification, for the same menu-caching reason as the project picker.
  • A shown run never records a trace (--trace off), as upstream does, and the two options exclude each other: turning Show browser on turns Show trace viewer off and closes its window; turning Show trace viewer on turns Show browser off and closes the kept browser. Only a folder default in settings can leave both on, and then runs record no trace and the first such run says so once.

Under the hood the extension starts one playwright run-server process per configuration from your project's own Playwright (in its extension mode, so the browser is reused across connections) and gives each run PW_TEST_CONNECT_WS_ENDPOINT and PW_TEST_REUSE_CONTEXT=1, exactly the hooks the VS Code extension uses. The process ends when you close the browsers, turn the option off, or quit Zed; if it dies on its own, a notification says so and the next run starts a new one. If it cannot start, you get one error notification with the command and the run does not start.

The choice is remembered per user in show-browser.json under the state directory. A folder or team default is the reuseBrowser key (the upstream setting name) of the settings block in Settings and applies until you toggle the option yourself.

#Terminal output (optional)

Extensions cannot write to Zed's terminal panel. Playwright: Show last run output gives you the same text in an editor tab; if you want a real terminal, add this task to ~/.config/zed/tasks.json. Zed already recognises test( and test.describe( calls in TypeScript and JavaScript files, so the gutter run button and the task: spawn picker will offer it:

[
  {
    "label": "Playwright: Run test at cursor with CLI output",
    "command": "npx",
    "args": ["playwright", "test", "$ZED_FILE:$ZED_ROW"],
    "cwd": "$ZED_WORKTREE_ROOT",
    "tags": ["js-test", "ts-test", "tsx-test"]
  }
]

#Limitations and differences from the VS Code extension

  • The executing step is marked with a trailing label, not a highlighted line: Zed has no decoration API for extensions, inlay hints are the closest native surface.
  • The run output opens as an editor tab, not in a Test Results panel, because Zed has no panel an extension could fill. The tasks recipe under Terminal output is the way to a real terminal.
  • Both surfaces are opt-in through Zed settings (code_lens, inlay_hints).
  • "Show trace viewer" is an entry in the ctrl-. menu rather than a checkbox in a settings view, and the trace of a particular test is chosen with the cursor rather than in a Test Explorer tree, because Zed has neither. The viewer window starts with the first trace to show instead of before the run.
  • "Show browser" and "Close all browsers" are ctrl-. entries for the same reason. Turning "Show trace viewer" on also turns "Show browser" off here, where the VS Code extension only has the opposite direction. While the browser is shown, the VS Code extension also turns video recording off; the command line has no switch for that, so a project that records video keeps doing so and Playwright then opens a fresh context per test instead of reusing one. The kept browser is closed by the action or by turning the option off; closing its last page by hand does not stop it (the next run simply opens a new page in it).
  • Zed caches the ctrl-. menu per cursor position, so the [x] marks of the project, trace viewer and browser toggles lag one toggle behind at an unchanged cursor; the confirmation notification shows the real state.
  • After an update or reinstall of the extension in the same Zed session, Zed keeps the Playwright server stopped until you run editor: restart language server (see Install).
  • Watch mode, pick locator, debugging, locator tuning and test recording are not implemented yet; see docs/parity.md for the status of every upstream capability.

#Getting help

Open an issue at https://github.com/radekBednarik/playwright-zed/issues. Helpful in a report:

  • Your Zed version (zed: about), the extension version (zed: extensions), your operating system, and the @playwright/test version of the project.
  • For problems with runs or discovery: the Playwright server log from dev: open language server logs (pick Playwright).
  • For problems with the extension itself (installation, the server not starting): zed: open log.
  • The playwright.config.* and a minimal test that shows the problem, if you can share them.

#Contributing and development

Everything below is for people who build or change the extension. Users do not need it.

#Building from the repository

Prerequisites: Rust with the wasm32-wasip2 target (rustup target add wasm32-wasip2), Node 22.12 or newer, Zed 1.23 or newer on the same machine as the clone (a Zed on Windows cannot load a dev extension from a WSL path).

  1. Build the server and the browser for the sample project: 
    (cd server && npm install && npm run build)
(cd fixtures/sample-project && npm install && npx playwright install chromium)
  2. To use the local server build instead of the published npm package, set PLAYWRIGHT_ZED_SERVER_ENTRY=<repo>/server/bin/playwright-zed-language-server.js. The extension reads it from the shell environment Zed loads for the project, so either export it in your shell profile (~/.bashrc, ~/.profile) or start zed from a shell where it is exported; a one-off export in another terminal is not enough.
  3. In Zed, run zed: install dev extension and pick the repository root. Zed compiles the Rust crate; the first build takes about a minute.

After a Rust change run zed: install dev extension again, then editor: restart language server (Zed keeps the server stopped after a reinstall, see Install). After a server change run npm run build and editor: restart language server. Problems with the extension itself appear in zed: open log; problems with runs appear in the Playwright server log.

  2. ctrl-shift-p, run zed: install dev extension, choose the repository root.

  3. zed: extensions must list Playwright Runner 0.8.0.

  4. zed: open settings, add "code_lens": "on".
