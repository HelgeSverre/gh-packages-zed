#Zed Polza.ai

Расширение Zed для Polza.ai: показывает баланс организации (GET /api/v2/balance) в панели агента. Ключ хранится в polza.yaml.

#Из чего состоит

ЧастьЧто делаетНужен ли Rust
server/polza-mcp.mjsMCP-сервер (stdio): инструменты polza_balance/polza_config и слеш-команда /polza_balanceнет
server/balance-cli.mjsCLI для ручной проверки и для слеш-командынет
.zed/tasks.json, scripts/balance-watch.mjsзапуск без агента: отчёт в терминале и баланс в заголовке вкладкинет
src/lib.rsрасширение Zed: слеш-команда /polza_balance + регистрация MCP-серверада

Рабочая слеш-команда /polza_balance приходит из MCP-сервера: Zed показывает MCP-промпты в списке команд панели агента. В актуальных сборках Zed слеш-команды расширений в панели агента не отображаются, поэтому Rust-часть нужна только для совместимости со старыми версиями.

MCP-сервер — самостоятельный Node-процесс: он читает polza.yaml, ходит в API и кэширует ответ на секунду. Слеш-команду /polza_balance он тоже обслуживает сам — как MCP-промпт. Rust-обёртка запускает тот же Node-скрипт и нужна только там, где Zed ещё показывал команды расширений.

#Быстрый старт (без Rust)

  1. Впишите ключ в polza.yaml:

    api_key: "ваш ключ Polza.ai"

  2. Добавьте сервер в settings.json Zed (файл settings.snippet.json):

    {
  "context_servers": {
    "polza-ai": {
      "command": "node",
      "args": ["D:/path/to/zed-polza-ai/server/polza-mcp.mjs"],
      "env": {
        "POLZA_CONFIG": "D:/path/to/zed-polza-ai/polza.yaml"
      }
    }
  }
}

    То же самое можно сделать через UI: Settings → AI → MCP Servers → Add Server → Add Local Server (command: node, args: путь к polza-mcp.mjs).

  3. Проверьте: Settings → AI → MCP Servers — индикатор polza-ai зелёный, в панели агента доступны инструмент polza_balance и команда /polza_balance.

#Слеш-команда /polza_balance

  • Наберите /polza_balance в панели агента и выберите «Баланс Polza.ai».
  • Сервер сам запрашивает баланс и подставляет готовый отчёт в сообщение — цифры берутся из API, а не придумываются моделью.
  • Команда засчитывается как один ход агента: Zed отправляет сообщение модели. Отчёт без модели и без траты токенов — задача Zed, см. ниже.
  • После изменения server/polza-mcp.mjs перезапустите сервер (Settings → AI → MCP Servers → выключить/включить polza-ai) или Zed.

Если Zed не находит node (частый случай на Windows без PATH для GUI-приложений), укажите абсолютный путь к нему в command, например C:/nvm4w/nodejs/node.exe.

#Проверка из терминала

node server/balance-cli.mjs           # отчёт по балансу
node server/balance-cli.mjs --check   # какой конфиг найден, какие пути проверены
node server/balance-cli.mjs --json    # машинный формат
node scripts/balance-watch.mjs        # вотчер: баланс в заголовке вкладки
node scripts/mcp-smoke.mjs            # смоук-тест MCP-протокола
node scripts/mcp-smoke.mjs --network  # + реальный запрос с неверным ключом (ждём 401)

#Без агента: задачи Zed

Слеш-команда в панели агента — это ход модели. Если нужен отчёт без модели и без траты токенов, используйте задачи Zed: они запускают команду в терминале.

В проекте уже есть .zed/tasks.json:

  • «Polza: баланс» — разовый отчёт (server/balance-cli.mjs);
  • «Polza: баланс в заголовке вкладки» — вотчер, который обновляет сумму в заголовке вкладки терминала (по умолчанию раз в 2 минуты, интервал задаётся POLZA_WATCH_INTERVAL_MS).

Запуск: task: spawn из командной палитры → выбрать задачу.

Горячая клавиша — в keymap.json:

{
  "context": "Workspace",
  "bindings": {
    "alt-b": ["task::Spawn", { "task_name": "Polza: баланс" }]
  }
}

task_name ищется среди задач, доступных в текущем проекте. Чтобы команда работала в любом проекте, добавьте задачу в глобальный tasks.json (zed: open tasks) с абсолютным путём:

[
  {
    "label": "Polza: баланс",
    "command": "node",
    "args": ["D:/projects/sandboxes/zed-polza-ai/server/balance-cli.mjs"],
    "reveal": "no_focus"
  }
]

polza.yaml ищется рядом со скриптом, поэтому путь к конфигу в глобальной задаче указывать не нужно.

#«Обновлять после каждого запроса»

Это ограничение платформы: у расширений Zed нет хука «после запроса к модели», нет статус-бара и нет возможности добавить свою панель. Поэтому автоматического индикатора не бывает в принципе.

Ближайшее рабочее решение — правило для агента: MCP-инструменты модель вызывает сама. Добавьте в AGENTS.md проекта (или в правила профиля):

После завершения каждой задачи, прежде чем ответить, вызывай инструмент
`polza_balance` и укажи в ответе доступный остаток Polza.ai.

Тогда после каждого хода агента (то есть после запросов к Polza.ai) в ответе будет свежий остаток. Минус — лишний вызов инструмента на каждый ход; при необходимости правило можно сделать мягче («раз в задачу»).

#Установка расширения (слеш-команда)

Нужен Rust и target wasm32-wasip2:

rustup target add wasm32-wasip2

Затем в Zed: командная палитра → zed: install dev extension → выбрать эту папку. После установки:

  • в панели агента появится /polza_balance (в сборках Zed, где команды расширений ещё поддерживаются);
  • в Settings → AI → MCP Servers появится сервер polza-ai (его нужно включить) — расширение само отдаёт команду запуска, править settings.json не надо;
  • в диалоге установки расширение попросит настроить polza.yaml — впишите ключ в файл рядом с расширением.

Расширение подставляет CARGO_MANIFEST_DIR на этапе сборки, поэтому оно рассчитано на установку как dev extension из этой папки. Для публикации в реестре расширений путь к скрипту нужно будет заменить на путь внутри extension work dir (или передавать скрипт через node -e).

#Где ищется polza.yaml

По порядку, первый найденный:

  1. POLZA_CONFIG (переменная окружения, может быть путём к файлу);
  2. <POLZA_EXTENSION_DIR>/polza.yaml (задаёт расширение);
  3. polza.yaml рядом с проектом расширения;
  4. %APPDATA%/Zed/polza.yaml;
  5. ~/.config/zed/polza.yaml, ~/.zed/polza.yaml, ~/.polza/polza.yaml;
  6. polza.yaml в текущем рабочем каталоге.

node server/balance-cli.mjs --check покажет, какой файл выбран и какие пути проверялись.

#Ограничения и мелочи

  • В корпоративной сети с MITM-прокси Node может ругаться SELF_SIGNED_CERT_IN_CHAIN. Сервер сам переключается на curl; альтернатива — запускать Node с --use-system-ca (Node 22.15+) или задать NODE_EXTRA_CA_CERTS с корневым сертификатом.
  • Ключ лежит в открытом YAML. Не коммитьте polza.yaml (он в .gitignore); для секретов лучше POLZA_API_KEY в окружении.
  • API-ключ в polza.yaml и ключ провайдера в settings.json (language_models.openai_compatible.POLZA) — разные записи, но один и тот же ключ Polza.ai.
  • Баланс в available уже учитывает резерв под выполняющиеся запросы; amount — полный остаток кошелька. Для «хватит ли денег» ориентируйтесь на available.
